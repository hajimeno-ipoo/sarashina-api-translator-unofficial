# Sarashina API 翻訳（非公式）

Sarashina APIを使って、Webページの文章を日本語・英語に翻訳するChrome／Safari拡張機能です。選択した文章の翻訳、入力欄への訳文の反映、原文の解説、訳文のニュアンスの確認に加え、英語にはカタカナ、日本語の漢字を含む語にはひらがなの読みを表示できます。

本プロジェクトは、個人が開発した非公式のブラウザ拡張機能です。SB Intuitions株式会社が提供・公認する製品ではありません。Sarashina APIを利用していますが、APIの提供元と本拡張機能の開発者は異なります。

利用には、ご自身のSarashina APIキーが必要です。

| ブラウザー | バージョン | 読み込む場所 |
|---|---|---|
| Google Chrome | 1.10.0 | リポジトリのルートフォルダ |
| Apple Safari（macOS） | 1.8.0 | `safari/`、または付属のXcodeプロジェクト |

## 実装済みの機能

### 選択した文章の翻訳

ページ内の文章を選択し、右クリックの「Sarashinaで選択部分を翻訳」を選ぶと、翻訳カードを表示します。Xのポストなど、Webページに表示されている文章にも使えます。

- 日本語 → 英語、英語 → 日本語、自動判定に対応。
- カード内で翻訳方向を変更し、同じ原文を再翻訳。
- 通信に失敗した場合の再試行。
- 訳文のコピー、カードの拡大・縮小。
- ショートカットで選択翻訳を起動。Macは `Option + Shift + Y`、その他は `Alt + Shift + Y`。
- アクセスが許可されたiframe内の選択にも対応。

### 選択部分を訳文に置き換える

訳文を確認して「原文を訳文に置き換える」を押すと、選択部分だけを差し替えます。ページ本文に加え、一行入力、複数行入力、`contentEditable` の編集欄に対応しています。

前後の文章は残し、「原文に戻す」で選択部分を復元できます。再翻訳後は「訳文を更新」で新しい訳文を反映します。入力欄の置き換えによって、投稿やメッセージの送信を行うことはありません。

復元は、そのカードが開いている間に行ってください。カードを閉じたり別の文章を選んだりすると、前の選択範囲の保存を解放します。編集中の文章がサイト側や利用者によって変わった場合、文字数上限を超える場合、読み取り専用の場合などは、上書きせず案内を表示します。編集欄の書式を完全に復元する機能ではありません。

### 原文の解説

カードの「解説」を押すと、原文の意味、理解に必要な用語、語気や慣用表現を日本語で説明します。翻訳済みなら訳文も参考にします。

右クリックの「Sarashinaで選択部分を解説」からは、翻訳を挟まず原文だけで実行できます。解説には `sarashina3-mini` を使用します。

### 訳文のニュアンス

翻訳結果の横にある「訳文のニュアンス」を押すと、原文と現在の訳文を比較し、訳語・丁寧さ・感情の強さ・必要に応じた別訳との違いを日本語で説明します。

`sarashina3-mini`を使い、既存の「解説」とは別に実行・表示します。両方の結果を残して読み比べられます。解説やニュアンスの確認に失敗しても訳文は保たれ、専用ボタンで再試行できます。再翻訳した場合は、前の説明を消します。

### 原文・訳文の文字数

選択翻訳カードの見出しに、それぞれの文字数を表示します。再翻訳や別の文章の選択に合わせて更新します。

数え方はUnicodeのコードポイント単位です。通常の絵文字 `😀` は1文字、肌色付きの `👍🏽` は2文字、家族の `👨‍👩‍👧‍👦` は7文字になります。文章内の空白と改行も数えますが、原文の先頭・末尾の空白と改行は既存処理で除去した後に数えます。改行はLFなら1、CRLFなら2です。画像生成サービスなどの入力上限と同じ数え方とは限りません。

### ページ全体の翻訳

右クリックメニュー、またはツールバーのポップアップから実行します。ページ上部の翻訳バーで、方向の切り替えと原文への復元を行えます。

ページ内の対象テキストを取り出して翻訳し、文字を書き換えます。スクリプト・入力欄・アイコン用の文字列などを除外する処理を含みます。動的に更新されるサイトでは、表示や復元がサイト側の再描画の影響を受ける場合があります。

### ポップアップでの手動翻訳

ツールバーのSarashinaアイコンを押し、文章を入力して翻訳できます。翻訳方向の指定と結果のコピーに対応しています。入力中は `Command + Enter` または `Ctrl + Enter` でも実行できます。

### 英語・日本語の読みを表示

ページ全体に付ける場合は、ツールバーのポップアップで「読みを表示」を押します。ページの文章を文脈とともにAIへ送り、元の文章の上に読みを表示します。英語にはカタカナ、日本語の漢字を含む語にはひらがなを付けます。日英が混ざる文章も対象です。

選択した文章だけに付ける場合は、ページ本文を選択し、右クリックの「Sarashinaで選択部分に読みを付ける」を押します。APIへ送る文章とルビを付ける範囲は、その選択部分だけです。選択モードでは、新しく追加された投稿などへ対象を広げません。

ページ内の操作バーで「読みを外す」を押すと、読みが消えてボタンが「再表示」に変わります。「再表示」を押すと、同じページで取得済みの読みを使って戻します。同じ文章へのAPI要求は増えません。ポップアップの「読みを外す」、ページ翻訳の開始、翻訳の原文復元では、読みと操作バーを取り除きます。

ページ全体モードで読みを表示している間は、後から追加された文章や変更された文章を自動で処理します。取得済みの文脈には保存した読みを使い、新しい文脈だけをAPIへ送ります。同じ単語でも周囲の文章が変われば、別の読み生成として扱います。非表示中はこの監視と新たな読み取得を止め、再表示時に最新の本文を確認します。

選択モードの「再表示」は、最後に読みを付けた同じ選択範囲へ戻します。元の文章が変更・削除されていた場合は選び直しを案内し、ページ全体への処理には切り替えません。別の範囲を選んで実行すると、前のルビ表示を解除して新しい範囲へ付けます。ポップアップの「読みを表示」でページ全体モードへ切り替えられます。

読みのキャッシュは、開いているページのメモリ内だけに保持します。ファイルやブラウザーの保存領域には書き込まず、ページ全体の再読み込みや別文書への移動で消えます。取得途中に非表示にした場合、すでに送った通信は取り消しません。遅れて届いた正常な返答は表示せず、同じページでの再表示に使います。

リンク・太字・ボタンの要素を残して、その中の文字へ `ruby`・`rt` を追加します。入力欄、編集可能領域、コード、アイコン、非表示部分、サイトに元からあるルビ、画像やCanvasの文字は読み付けの対象外です。ページ全体モードではiframe内も対象外です。単語が複数の文字ノードに分かれている箇所や、読みを取得できなかった箇所は省略する場合があります。固有名詞や文脈による読み分けが常に正しいこと、すべてのサイトで同じ表示・操作を保てることは保証しません。

## 導入方法

リポジトリをダウンロードして展開するか、次のコマンドで取得します。

```bash
git clone https://github.com/hajimeno-ipoo/sarashina-api-translator-unofficial.git
```

### Chrome

1. `chrome://extensions` を開きます。
2. 右上の「デベロッパーモード」を有効にします。
3. 「パッケージ化されていない拡張機能を読み込む」を押します。
4. ルートの `manifest.json` が入っている `sarashina-api-translator-unofficial` フォルダを選びます。`safari/` は選びません。
5. ツールバーにSarashinaを固定し、設定画面を開きます。

手順の参考：[Chrome公式の拡張機能読み込みガイド](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-unpacked)

### Safari

Safari 18.4以降のmacOSでは、`safari/` フォルダを一時拡張として読み込めます。Xcodeを使う場合は、付属のプロジェクトからアプリをビルドして実行します。

どちらの方法も、詳細は [Safari導入ガイド](safari/README_SAFARI.md) を参照してください。付属Xcodeプロジェクトの現在のmacOS Deployment Targetは親プロジェクトが27.0であり、より古いmacOSでのビルド・実行はこの設定のままでは対象外です。一時拡張の読み込みとは別の条件です。

## API設定

1. 拡張機能の設定画面でAPIキーを入力します。`Bearer` は付けません。
2. APIベースURLを確認します。既定値は `https://api.sarashina.ai/v1` です。
3. 翻訳モードを選びます。
4. 「接続テスト」を押します。SafariでAPIサイトへのアクセスを求められた場合は許可します。
5. **「設定を保存」を押します。接続テストだけでは設定は保存されません。**

| 処理 | 使用するモデル |
|---|---|
| 専用Translate APIでの翻訳 | `sarashina3-translate` |
| Chat Completionsでの翻訳 | 設定で `sarashina3-mini` または `sarashina3-nano` を選択 |
| 解説・訳文のニュアンス | 翻訳設定とは独立して `sarashina3-mini` を使用 |
| 英語・日本語の読み生成 | 翻訳設定とは独立して `sarashina3-mini` のChat Completionsを使用 |

## データの取り扱いと動作上の制限

- 翻訳・解説・読み生成の対象文章は、設定したAPIベースURLへ外部送信します。既定の送信先はSarashina APIです。ページ全体翻訳と読み生成では抽出した対象テキスト、解説・ニュアンスでは原文と必要に応じて訳文を送ります。
- ページ全体モードの読み表示中は、後から追加・変更された対象文章も自動でAPIへ送信します。ページに表示された文章には、投稿本文やアカウント名などが含まれる場合があります。「読みを外す」で新たな読み取得を止められます。
- 選択範囲への読み付けでは、選択部分だけを送信し、ページの追加文章への自動送信は行いません。
- 解説とニュアンスは、それぞれのボタンを押したときに追加のAPI通信を行います。
- APIキーと設定は拡張機能の `storage.sync` に保存します。端末内だけの保存を保証するものではなく、ブラウザーの設定や実装に応じて同期される場合があります。
- WebページとAPIサイトへのアクセス許可が必要です。ブラウザーの設定画面など、拡張機能の実行が禁止されているページでは動作しません。
- 言語の自動判定は文字の種類と数による簡易方式です。混在文で意図と異なる場合は、翻訳方向を指定してください。
- 翻訳・解説・読みはモデルの出力です。文脈が不足する文章や専門的な文章では、原文と照らして確認してください。

APIへの入力・出力の取り扱いは、[Sarashinaサービス利用規約](https://sarashina.ai/terms)と提供元の案内をご確認ください。利用するWebサイトの規約も適用されます（例：[X利用規約](https://x.com/ja/tos)）。本拡張機能はSB Intuitions株式会社の提供・公認製品ではありません。

## 更新後の反映

Chromeでは拡張機能を再読み込みし、翻訳対象のページも再読み込みします。Safariの一時拡張は再読み込みまたは再追加し、対象ページを再読み込みします。Xcode版は再ビルド・実行後に対象ページを再読み込みしてください。

## ソース構成

```text
sarashina-api-translator-unofficial/
├── manifest.json              # Chrome版
├── background.js              # API通信・メニュー・メッセージ処理
├── content.js                 # 選択カード・ページ翻訳
├── selection-replacement.js   # 選択範囲の保存・置換・復元
├── reading.js                 # 読み表示・ページ内キャッシュ・本文変更の監視
├── popup.html / popup.js      # ポップアップ
├── options.html / options.js  # API設定
├── content.css / icons/
├── safari/                    # Safari版ソース・導入ガイド
├── Safari_App/                # SafariアプリのXcodeプロジェクト
└── tests/                     # API処理の回帰テスト・読み表示のDOMテスト
```

拡張機能自体にnpmの依存パッケージやビルド処理はありません。以下のコマンドはリポジトリのルートで実行します。

### API処理のテスト

Node.jsの標準機能だけで実行できます。Playwrightやブラウザーは不要です。

```bash
node --test tests/safari-connection.test.cjs tests/reading-api.test.cjs
```

テストは拡張機能APIと翻訳APIの応答を模擬して検証します。実際のブラウザーへの導入や、認証済みAPIによる出力品質の確認とは別です。

### 読み表示のDOMテスト

Node.jsに加え、導入済みのPlaywrightと、それに対応するChromiumが必要です。`PLAYWRIGHT_MODULE`にはPlaywrightのモジュールディレクトリを指定します。標準のブラウザー配置を使わない場合は、`READING_CHROMIUM_EXECUTABLE`へChromium実行ファイルのパスも指定できます。テスト自身は依存パッケージやブラウザーをダウンロードしません。

```bash
PLAYWRIGHT_MODULE="$(npm root)/playwright" \
READING_TEST_BROWSERS=chromium \
node --test tests/reading-dom.test.cjs
```

この例は、Playwrightを現在のプロジェクトの `node_modules` に導入済みの場合です。別の場所にあるモジュールを使う場合は `PLAYWRIGHT_MODULE` を変更してください。試験用ページと模擬API応答を使い、実APIキーは必要ありません。

### 確認できた範囲

2026年10月16日、公開用の現ソースに対し、API処理の模擬テスト99件と、Chromiumでの読み表示のDOMテスト33シナリオが成功しました。DOMテストには表示・復元、元のリンクとボタンの維持、キャッシュ再利用、追加・変更文への追従、遅延応答と通信失敗、ページ内バーの「読みを外す」→「再表示」、選択部分だけの送信と表示、非表示テキストの除外、選択モードで範囲を広げないことが含まれます。これらは実APIの読みの正確さを測る試験ではありません。

実APIでは、ローカルの確認用ページで読みの生成・表示・解除を確認しました。別途、Chrome版1.9.0相当を読み込んだEgoブラウザーで、利用者が外部送信を承認したX「話題を検索」の1ページについて、読み表示、非表示後のキャッシュ再利用、スクロールで追加された投稿への自動付与を確認しました。その時点で読み込まれた範囲の確認であり、X全体やすべての動的サイトの対応を示すものではありません。

ページ内バーの「再表示」と選択部分の読み付けは、その後に追加した機能で、上記の模擬DOM試験で確認しています。X実ページでのこれらの操作と、Safari本体での読み付け・自動追従は未確認です。Safari版の署名なしDebugビルドと組み込みファイルの一致は、過去の1.7.0時点で確認しました。現行1.8.0では再ビルドしていません。
